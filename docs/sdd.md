## 1. Введение {#1-introduction}

### 1.1 Назначение документа {#11-document-purpose}

Настоящий SDD описывает архитектуру и проектные решения сервиса «КиноВектор» версии 1.0 (MVP). Документ предназначен для архитектора, разработчиков, тестировщиков и сопровождающего персонала: он задаёт границы системы, модули, данные, интерфейсы и поведение, достаточные для реализации и проверки системных требований. SDD дополняет SRS v1.0 и реестр системных требований; конкретные проектные решения вынесены в ADR-001…ADR-007.

### 1.2 Область применения {#12-subject-scope}

Проектируемая система – веб-сервис персональных рекомендаций фильмов. В MVP входят регистрация и вход, каталог с поиском и фильтрами, карточка фильма, оценки, рецензии с модерацией, история просмотров, онбординг предпочтений, персональная лента с объяснениями, ночной пересчёт, администрирование каталога, импорт TMDB по ID, экспорт и удаление данных, аналитика, подборки, дайджест и поиск по актёрам и режиссёрам. Внешними системами являются TMDB API, SMTP-сервер и S3-совместимое хранилище. Релиз 2 включать восстановление пароля, аватар, поиск TMDB по названию, мобильное приложение и Collaborative-фильтрацию; они в дизайн MVP не входят.

## 3. Проектные представления {#3-design-views}

### DV-01. Контекст системы

- **ID**: DV-01-context
- **Title**: Границы сервиса и внешние акторы
- **Viewpoint**: Контекст
- **Representation**: Система «КиноВектор» – чёрный ящик. Внешние акторы: зритель (гость и зарегистрированный пользователь), контент-администратор, модератор, TMDB API, SMTP-сервер, S3-совместимое хранилище. Сервис предоставляет каталог, персонализацию, оценки, рецензии, подборки, дайджест и административные функции. Граница проходит по HTTPS-интерфейсу: всё, что вне сервиса, считается внешней системой. Графика: `report/typst/img/context.png`.
- **More Information**: Требования SYS-F-01…SYS-F-24, SYS-NF-10; решение ADR-001. Реализовано в SRS REQ-FUNC-001…REQ-FUNC-010.

### DV-02. Композиция модулей

- **ID**: DV-02-composition
- **Title**: Модульный монолит и распределение ответственности
- **Viewpoint**: Композиция
- **Representation**: Один процесс Drogon, содержащий модули: `auth` (F-01, F-19), `catalog` (F-04…F-07, F-24), `social` (F-08…F-10, F-22), `recommend` (F-12…F-15, F-23), `admin` (F-16, F-17), `notify` (F-21, F-23), `analytics` (F-18, F-20), `platform` (NF-01…NF-05). Модули обмениваются через внутренние сервисные интерфейсы и общую транзакционную БД. Функциональная декомпозиция задана модулями; ранняя декомпозиция – одним контейнером и пулом потоков Drogon. Зависимости направлены от верхних модулей к `platform`; циклы запрещены.
- **More Information**: SYS-NF-08, ADR-001, ADR-003. Границы проверяются архитектурными тестами в CI.

### DV-03. Логическое представление

- **ID**: DV-03-logical
- **Title**: Ключевые абстракции предметной области
- **Viewpoint**: Логическое представление
- **Representation**: Классы/сущности: `User`, `Movie`, `Rating`, `Review`, `WatchHistory`, `Preference`, `Recommendation`, `Collection`, `Digest`, `Actor`, `Director`. Сервисы: `AuthService`, `CatalogService`, `RatingService`, `RecommendationService`, `CollectionService`, `AdminService`, `NotificationService`. Контроллеры Drogon принимают DTO и делегируют сервисам; репозитории изолируют доступ к PostgreSQL и Redis. Наследование не применяется; используются композиция и интерфейсы репозиториев.
- **More Information**: SYS-F-01…SYS-F-24, ADR-002, ADR-005. Подборки и дайджест добавлены CR-04.

### DV-04. Информационное представление

- **ID**: DV-04-information
- **Title**: Логическая модель данных
- **Viewpoint**: Информация
- **Representation**: Основные таблицы PostgreSQL: `users`, `movies`, `genres`, `movie_genres`, `ratings`, `reviews`, `watch_history`, `preferences`, `recommendations`, `collections`, `collection_movies`, `actors`, `directors`, `movie_actors`, `movie_directors`, `digest_log`. Связи: `users` 1…N `ratings`, `reviews`, `watch_history`, `collections`; `movies` 1…N `ratings`, `reviews`, `collection_movies`; `movie_actors` и `movie_directors` реализуют связь многие-ко-многим. Индексы: по `title` (trigram), `genre_id`, `release_year`, `rating`, `actor_id`, `director_id`. Хранение персональных данных – 30 дней, затем анонимизация. Redis хранит `session:*` (TTL 24 ч), `tmdb:*` (TTL 24 ч), `popular:*` (TTL 1 ч).
- **More Information**: SYS-F-08, F-22, F-24, F-19, SYS-NF-07; ADR-003. Схема мигрируется через SQL-файлы в `platform`.

### DV-05. Интерфейсы

- **ID**: DV-05-interface
- **Title**: Внешние и внутренние контракты
- **Viewpoint**: Интерфейс
- **Representation**: Внешний интерфейс – REST/JSON по HTTPS: `/api/auth/*`, `/api/movies`, `/api/movies/{id}`, `/api/ratings`, `/api/reviews`, `/api/collections`, `/api/recommendations`, `/api/admin/*`. Браузер использует Vue.js 3 и Bootstrap 5, данные получает через REST/JSON. Интеграции: TMDB `GET /movie/{id}` с таймаутом 3 с и кэшем 24 ч; SMTP для писем; S3 для постеров. Внутренние интерфейсы – C++-интерфейсы репозиториев и сервисов с DTO. Ошибки возвращаются в формате `{ "error": code, "message": text }`.
- **More Information**: SYS-NF-10, SYS-F-17, SYS-F-23, ADR-002, ADR-006, ADR-007. Полный контракт SUPPLEMENT в разделе 5.

### DV-06. Взаимодействие

- **ID**: DV-06-interaction
- **Title**: Последовательность ключевых сценариев
- **Viewpoint**: Взаимодействие
- **Representation**: Сценарий «Оценка фильма»: браузер → `RatingController` → `AuthService` (проверка роли) → `RatingService` → PostgreSQL (транзакция: вставка оценки, пересчёт среднего) → `RecommendationService` (инвалидация кэша) → ответ. Сценарий «Лента»: браузер → `RecommendController` → `RecommendationService` → Redis (`popular:*` / `recommendations`) → при отсутствии данных fallback на content-based скоринг → HTML с объяснениями. Сценарий «Импорт TMDB»: админка → `AdminService` → адаптер TMDB → mock/real API → предпросмотр → подтверждение → PostgreSQL + S3. Путь отказа: таймаут 3 с → fallback на локальные данные и запись в логи. Ошибка валидации возвращается пользователю без изменения состояния.
- **More Information**: SYS-F-08, SYS-F-14, SYS-F-17, SYS-F-22; ADR-005, ADR-006.

### DV-07. Развёртывание

- **ID**: DV-07-deployment
- **Title**: Инфраструктура и конвейер поставки
- **Viewpoint**: Развёртывание
- **Representation**: Docker Compose поднимает четыре сервиса: `app` (C++20/Drogon), `postgres:16`, `redis:7`, `worker` (ночной пересчёт и дайджест). Reverse proxy terminating TLS 1.3 направляет трафик на `app`. Статика и постеры – S3-совместимое хранилище. CI (CMake + ctest) собирает образ, прогоняет модульные и архитектурные тесты, миграции и публикует артефакт. Конфигурация окружения задаётся переменными; секреты – вне репозитория. Масштабирование – горизонтальное копирование `app` при сохранении общего PostgreSQL/Redis.
- **More Information**: SYS-NF-02, NF-04, NF-05; ADR-001, ADR-003. Стоимость инфраструктуры 960 $ заложена в план.

### DV-08. Алгоритм и ресурсы

- **ID**: DV-08-algorithm
- **Title**: Content-based скоринг и бюджет ресурсов
- **Viewpoint**: Алгоритм / Ресурсы
- **Representation**: Скоринг кандидата: `score = 0,30·genre + 0,25·rating + 0,25·history + 0,20·preference`. Жанры сравниваются по вектору предпочтений; история – по недавно просмотренным фильмам; preference – онбординг. Кандидаты – фильмы с score > порога, fallback – популярные. Объяснения строятся по доминирующему признаку. Ночной пересчёт запускается worker, результат пишется в `recommendations`. Ресурсы: 4 потока Drogon, пул PostgreSQL 20 соединений, Redis до 100 MB, p95 каталога ≤ 500 мс, ленты ≤ 800 мс при 100 одновременных пользователях. Конфигурируемые веса позволяют заменить алгоритм в релизе 2.
- **More Information**: SYS-F-14, F-15, F-23, SYS-NF-01, NF-09; ADR-005. Метрики NDCG\@10 ≥ 0,30, coverage ≥ 50 %.
