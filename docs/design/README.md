# Графические артефакты и модель

В каталоге собраны материалы к SRS сервиса «КиноВектор». Вся графика
строится из одного исполняемого источника — SysML v2-модели; отдельных
PlantUML- или HTML-исходников нет.

- `kinovector.sysml` — SysML v2-модель предметной области, участников,
  внешних систем, интерфейсов, вариантов использования, ключевых
  требований, а также пользовательского интерфейса и представлений;
- `diagrams/` — PNG-изображения контекстной диаграммы и диаграммы
  вариантов использования;
- `mockups/` — PNG-мокапы четырёх экранов интерфейса;
- `render.py`, `render.sh` — сборка PNG из модели.

## Представления модели

| Представление | Что показывает | Как отрисовано |
|---------------|----------------|----------------|
| `ContextView` | границы системы, пять категорий пользователей, пять внешних систем и связи с ними | interconnection, `collapsed = true` для участников и внешних систем |
| `UseCaseView` | 13 вариантов использования, пять акторов, связи `include` и `extend` | interconnection с общими узлами акторов |
| `RecommendationsView` | экран персональных рекомендаций | мокап 1440 × 1200 px |
| `CatalogView` | экран каталога с фильтрами и сеткой фильмов | мокап 1440 × 1200 px |
| `MovieCardView` | карточка фильма с оценками, рецензиями и похожими фильмами | мокап 1440 × 1200 px |
| `ProfileView` | профиль, статистика, предпочтения, история и управление данными | мокап 1440 × 1200 px |

Мокапы описаны как структуры частей: каждый экран — это `part` с
вложенными элементами интерфейса. Координаты, размеры и цвета задаются
метаданными `DiagramLayout` (`@Canvas`, `Layout`, `Style`), поэтому PNG
воспроизводится из модели без ручной вёрстки.

## Перегенерация

Требуются OpenSysML CLI (`sysml`), Python 3 и Graphviz (`dot`, `neato`).
Проверено с OpenSysML CLI 0.12.1 и Graphviz 16.1.0. Если `sysml` не
установлен в `PATH`, укажите путь переменной `SYSML`:

```bash
SYSML=/path/to/sysml docs/design/render.sh
```

Скрипт вызывает `sysml -render <View> -render-form dot -render-style cameo`,
затем `dot` (для диаграмм) или `neato -n` (для позиционированных мокапов).
Промежуточные DOT-файлы создаются во временном каталоге и в репозиторий не
попадают.

Диаграмма вариантов использования строится как interconnection-представление:
так акторы остаются общими узлами, а не дублируются для каждого варианта
использования. Связи `include` и `extend` помечаются на этапе подготовки
DOT-файла, поскольку interconnection-рендерер не выводит для них подписи.

## Связь с требованиями

- контекстная диаграмма и SysML-модель — разделы 2.1, 2.2, 2.4 и 3 SRS;
- диаграмма вариантов использования — REQ-FUNC-001…010;
- мокапы — REQ-INT-001, REQ-FUNC-002, REQ-FUNC-003, REQ-FUNC-007, REQ-FUNC-010.
