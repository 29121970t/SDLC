# Серверный HTML и HTMX вместо одностраничного приложения

## Контекст и постановка задачи

Интерфейс сервиса включает каталог с фильтрами, карточки фильмов, формы оценок и рецензий, администрирование и персональную ленту (SYS-F-04…SYS-F-09, SYS-F-14, SYS-F-16). Требуется обеспечить адаптивность, клавиатурную навигацию и контраст (SYS-NF-06) при ограниченном фронтенд-ресурсе – один специалист на 12 недель. Необходимо выбрать подход к построению UI, совместимый со стеком C++/Drogon и дающий предсказуемое время разработки. Проектное представление: DV-03, DV-08.

## Драйверы решения

* Один frontend-специалист и жёсткий срок 12 недель.
* Требования доступности: адаптивная вёрстка, клавиатурная навигация, контраст (REQ-COMP-001, SYS-NF-06).
* Простота интеграции с серверными шаблонами Drogon.
* Необходимость частичной интерактивности без полной перезагрузки страницы.
* Ограничение инфраструктуры – не более 960 $ на проект.

## Рассмотренные варианты

* Серверный HTML с HTMX и Bootstrap 5.
* Одностраничное приложение на React с REST API.
* Классические формы с полной перезагрузкой страницы без HTMX.

## Итог решения

Выбран вариант «Серверный HTML с HTMX и Bootstrap 5», потому что он даёт интерактивность AJAX-запросов без отдельной frontend-сборки и дублирования валидации. React потребовал бы отдельный конвейер сборки, управление состоянием и дополнительное время на тестирование, что несовместимо с одним frontend-разработчиком. Классические формы проигрывают по пользовательскому опыту при фильтрации каталога.

### Последствия

* Хорошо, потому что бизнес-логика и валидация остаются на сервере в одном месте.
* Хорошо, потому что Bootstrap 5 обеспечивает адаптивность и базовую доступность из коробки.
* Плохо, потому что интерактивность ограничена возможностями HTMX и требует аккуратной работы с состоянием.
* Плохо, потому что большие изменения страницы всё же требуют полной перезагрузки.

### Подтверждение

Соответствие проверяется на демо итерации 2 и 5, а также осмотром разметки (I) и автоматическими проверками контраста и наличия aria-атрибутов. Нагрузочный тест NF-01 подтверждает, что серверный рендеринг укладывается в p95 ≤ 500 мс.

## Плюсы и минусы вариантов

### Серверный HTML с HTMX и Bootstrap 5

* Хорошо, потому что не требует отдельного JS-приложения и сборки.
* Хорошо, потому что переиспользует серверные шаблоны и валидацию.
* Нейтрально, потому что подходит для карусели и подборок через hx-get.
* Плохо, потому что сложные сценарии дайджеста и аналитики требуют серверной логики.

### Одностраничное приложение на React

* Хорошо, потому что даёт насыщенную интерактивность и кэширование на клиенте.
* Нейтрально, потому что API уже спроектировано в DV-05.
* Плохо, потому что требует второго конвейера сборки и дублирования валидации.
* Плохо, потому что не укладывается в доступный фронтенд-ресурс.

### Классические формы

* Хорошо, потому что проще всего в реализации и отладке.
* Нейтрально, потому что полностью совместимы с Drogon.
* Плохо, потому что фильтры каталога перезагружают страницу и ухудшают UX.
* Плохо, потому что не соответствуют ожиданиям заказчика по интерактивности.
