# Запросы на изменение требований

## Сервис рекомендаций фильмов «КиноВектор»

Версия 1.0

Подготовил: Красько А. П.

Дата: 2026-11-19

## Назначение

Документ фиксирует изменения базовой линии после согласования SRS v1.0. Каждый запрос содержит причину, затронутые требования, анализ влияния на объём, срок и стоимость, а также решение заказчика. Изменения внесены в реестр системных требований, SDD, ADR и план итераций.

## Процесс управления изменениями

1. Заказчик или исполнитель формулирует запрос и указывает причину.
2. Исполнитель анализирует влияние на требования, архитектуру, план и стоимость.
3. Заказчик принимает, отклоняет или откладывает запрос.
4. Принятый запрос обновляет базовую линию; отклонённый сохраняется в истории.
5. Изменения фиксируются в истории версий затронутых документов.

## CR-01. Упрощение рекомендательного модуля

| Поле | Значение |
|------|----------|
| Дата | 2026-11-04 |
| Инициатор | Заказчик |
| Затронутые требования | SYS-F-14, REQ-FUNC-007, REQ-ML-001, REQ-ML-002 |
| Причина | Оценка 18 чел.-дней признана высокой; заказчик попросил объяснить и предложить варианты |
| Решение | Гибридный рекомендатель заменён на content-based; объяснения сохранены |
| Влияние на объём | −6 чел.-дней (18 → 12) |
| Влияние на срок | 0, высвобожденные дни направлены в резерв |
| Влияние на стоимость | −1 140 $ |
| Статус | Принят 2026-11-05 |

**Обоснование.** Гибридный алгоритм требует матрицы совместных оценок, обработки разреженности и холодного старта. Для MVP достаточно content-based подхода: жанры, оценки пользователя, история просмотров и предпочтения. Объяснения формируются по тем же признакам. Целевое значение NDCG@10 снижено с 0,35 до 0,30, coverage – с 60 % до 50 %.

**Последствия.** ADR-004 переведён в статус `superseded by ADR-005`. В SDD обновлены представления DV-03 и DV-06.

## CR-02. Импорт TMDB только по идентификатору

| Поле | Значение |
|------|----------|
| Дата | 2026-11-04 |
| Инициатор | Заказчик |
| Затронутые требования | SYS-F-17, REQ-FUNC-009, REQ-INT-002 |
| Причина | Оценка 11 чел.-дней; заказчик ожидал более быстрый импорт |
| Решение | В MVP импорт по TMDB ID с предпросмотром; импорт по поисковому запросу – релиз 2 |
| Влияние на объём | −3 чел.-дня (11 → 8) |
| Влияние на срок | 0 |
| Влияние на стоимость | −570 $ |
| Статус | Принят 2026-11-05 |

**Обоснование.** Поиск по TMDB требует отдельного сценария выбора, обработки неоднозначных результатов и дополнительного тестирования. Администратор может найти фильм на сайте TMDB и вставить ID; этого достаточно для наполнения каталога в MVP.

**Последствия.** ADR-006 дополнен ограничением «import by ID only». В SDD обновлены DV-05 и DV-07.

## CR-03. Перенос восстановления пароля и аватара в релиз 2

| Поле | Значение |
|------|----------|
| Дата | 2026-11-04 |
| Инициатор | Исполнитель |
| Затронутые требования | SYS-F-03, SYS-F-02, REQ-FUNC-001 |
| Причина | Не влияет на первый запуск; снижает объём MVP |
| Решение | В MVP остаются вход, регистрация и отображаемое имя; восстановление пароля и аватар – релиз 2 |
| Влияние на объём | −6 чел.-дней (F-03 – 4, аватар – 2 из оценки F-02) |
| Влияние на срок | 0 |
| Влияние на стоимость | −1 140 $ |
| Статус | Принят 2026-11-05 |

**Обоснование.** Восстановление пароля требует отдельного токена, письма и сценария сброса; аватар – хранения файлов и модерации изображений. Для запуска достаточно подтверждения email и отображаемого имени.

**Последствия.** F-03 и аватар вынесены из базовой линии MVP, но остаются в реестре как требования релиза 2. В плане итераций освобождены 6 чел.-дней.

## CR-04. Добавление подборок, дайджеста и поиска по актёрам

| Поле | Значение |
|------|----------|
| Дата | 2026-11-17 |
| Инициатор | Заказчик |
| Затронутые требования | SYS-F-22, SYS-F-23, SYS-F-24, SYS-NF-09 |
| Причина | Заказчик после демо вспомнил о важной функциональности для запуска |
| Решение | Добавить публичные подборки, еженедельный дайджест и поиск по актёрам и режиссёрам |
| Влияние на объём | +36 чел.-дней (14 + 8 + 6 + 8) |
| Влияние на срок | Без junior – +2 недели; с junior – 0 |
| Влияние на стоимость | Без junior – +9 640 $ (48 220 $); с junior – +4 120 $ (42 700 $) |
| Статус | Принят 2026-11-19 |

**Обоснование.** Подборки повышают вовлечённость и дают пользователям возможность делиться вкусами; дайджест возвращает пользователей в сервис; поиск по актёрам и режиссёрам закрывает частый сценарий выбора фильма. Регрессия и интеграционные тесты выделены отдельным требованием NF-09.

**Последствия.** Добавлены представления DV-04 и DV-05, обновлены ADR-003 и ADR-005. План пересобран, добавлен junior-разработчик (CR-05).

## CR-05. Добавление junior-разработчика

| Поле | Значение |
|------|----------|
| Дата | 2026-11-19 |
| Инициатор | Исполнитель |
| Затронутые требования | Все требования MVP, ограничение BR-06 по составу команды |
| Причина | Заказчик отказался сдвигать deadline и увеличивать стоимость более чем на 2–3 % |
| Решение | Добавить одного junior-разработчика на 12 недель; senior-команда сохраняет состав |
| Влияние на объём | 50 чел.-дней junior + 12 чел.-дней наставничества |
| Влияние на срок | 0, deadline 2027-02-01 сохраняется |
| Влияние на стоимость | +4 120 $ к изменённому плану; +700 $ к первоначальному бюджету |
| Статус | Принят 2026-11-19 |

**Обоснование.** Junior выполняет 50 чел.-дней рутинных задач: CRUD-формы, тестовые данные, регрессия, шаблоны писем, импорт-скрипты. Senior-разработчики тратят 12 чел.-дней на наставничество и ревью. Экономия на ставке покрывает накладные расходы, поэтому стоимость остаётся в пределах первоначального бюджета.

**Последствия.** Ограничение SRS «команда из четырёх человек» пересмотрено: на время MVP команда состоит из четырёх senior-специалистов и одного junior. План итераций пересобран, добавлены контрольные точки наставничества.

## CR-06. Пересмотр приоритетов после первого раунда

| Поле | Значение |
|------|----------|
| Дата | 2026-11-05 |
| Инициатор | Заказчик |
| Затронутые требования | SYS-F-06, F-11, F-16, F-18, F-19, F-20, F-10, F-13, F-15 |
| Причина | Заказчик уточнил ценность функций после ознакомления со сроками |
| Решение | Повышены приоритеты фильтров, истории и админки; понижены аналитика и экспорт |
| Влияние на объём | 0 |
| Влияние на срок | 0 |
| Влияние на стоимость | 0 |
| Статус | Принят 2026-11-05 |

**Обоснование.** Фильтры и история напрямую влияют на время выбора фильма, админка – на наполнение каталога. Аналитика важна, но не блокирует запуск; экспорт данных остаётся обязательным по законодательству, поэтому сохраняет приоритет 40.

**Последствия.** Изменены приоритеты в реестре; порядок итераций скорректирован без изменения общего объёма.
